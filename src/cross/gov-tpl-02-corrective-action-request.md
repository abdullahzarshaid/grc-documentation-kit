*Guidance notes are in italics. One form per nonconformity. The reference is assigned by the Information Security Manager from GOV-REG-03. Attach evidence rather than describing it.*

## 1. Corrective action request

| Field | Entry |
|---|---|
| **Reference** | [CAR ID from GOV-REG-03] |
| **Source** | [Internal audit, External audit, Incident, Management review, Complaint, Monitoring, Supplier review, Other] |
| **Source reference** | [Audit ID, incident ID, review date or complaint reference] |
| **Raised by** | [Name], [Role] |
| **Date raised** | [Date] |
| **Grade** | [Major, Minor, Observation, Opportunity] |
| **Area, system or process affected** | [Text] |
| **Statement of nonconformity** | *What was observed, where and when. State facts, not opinions. One nonconformity per form.* |
| **Evidence** | *Record identifiers, screenshots, log extracts or interview notes that show the nonconformity. Attach, do not paraphrase.* |
| **Requirement breached** | *The clause, control, criterion or kit document statement, quoted by reference, for example GOV-PRO-10 step 4.6 or ISO/IEC 27001:2022 Annex A 5.18.* |
| **Personal data involved** | [Yes or No]. *If Yes, the Privacy Officer co-owns this form and decides whether PIMS-PRO-04 applies.* |
| **Action owner** | [Name], [Role] |
| **Immediate correction** | *What was done to contain the problem and restore the control. Within five working days for a major, twenty for a minor.* |
| **Correction date** | [Date] |
| **Corrective action required?** | [Yes or No]. *Reasons: could it recur, has it occurred before, could the same cause exist elsewhere, what would recurrence cost. A major always requires corrective action.* |
| **Root cause analysis method** | [Five whys, Fishbone, Other] |
| **Root cause** | *The cause the organisation can act on. "Human error" is not a root cause; say why the error was possible and not caught.* |
| **Same cause elsewhere?** | [Yes or No]. *If Yes, list the linked GOV-REG-03 references raised for the other areas.* |
| **Corrective action plan** | *Numbered actions. For each: what, who, by when, resources needed. Due within thirty days of raising for a major, ninety for a minor, unless an extension is approved below.* |
| **Plan owner** | [Name], [Role] |
| **Due date** | [Date] |
| **Extension approved by and reason** | [Name], [Role], [Date], [Reason] or "none" |
| **Documents and risks updated** | *Kit document IDs changed under GOV-PRO-01 and GOV-REG-05 risk IDs updated.* |
| **Implementation evidence** | *Attach evidence for each completed action, with dates.* |
| **Implementation complete date** | [Date] |

## 2. Verification of effectiveness

*Performed by someone other than the action owner, after at least ninety days of operation or three operating cycles.*

| Field | Entry |
|---|---|
| **Verifier** | [Name], [Role] |
| **Verification date** | [Date] |
| **Method** | *Records sampled (population and sample size), interviews held, configuration or output inspected.* |
| **Has the nonconformity recurred?** | [Yes or No], with evidence |
| **Does the control now operate as intended?** | [Yes or No], with evidence |
| **Result** | [Effective, Not effective]. *Not effective returns the form to root cause analysis.* |

## 3. Closure

| Field | Entry |
|---|---|
| **Closed by** | [Name], [Role]. *Information Security Manager for a minor, executive sponsor for a major.* |
| **Closure date** | [Date] |
| **Signature** | [Signature] |
| **GOV-REG-03 status set to** | Closed |

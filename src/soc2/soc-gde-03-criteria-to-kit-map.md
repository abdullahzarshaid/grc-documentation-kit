## 1. How to read this map

Each table lists the criteria of one category. The theme column is a reminder in plain words of what the criterion is about; it is not the criterion's text, which belongs to its publisher and should be read in the original when writing controls. The documents column names the kit policies, procedures, guides and templates that implement the theme. The registers column names the registers and records that evidence it. Where this kit has no dedicated document, the entry says which general document carries the theme.

Use the map in three places: when filling the Kit documents column of SOC-REG-01, when answering a request from SOC-GDE-02, and when running the gap assessment in PB-03. The kit does not replace the criteria; an organisation writing controls reads the criteria and their points of focus for itself.

## 15. Where the kit is thin

Three themes are carried by general documents rather than dedicated ones, and an organisation may want to add its own. Fraud risk (CC3.3) is a scenario class inside GOV-PRO-05 and a segregation rule inside GOV-PRO-10; an organisation handling payments should add explicit fraud scenarios to GOV-REG-05. Anomaly analysis (CC7.2) rests on GOV-PRO-14's alert triage; a larger operation will want a written triage runbook. Processing specifications (PI1.1) are required by SOC-POL-01 but have no template in the kit; the output and input catalogues in SOC-PRO-03 and SOC-PRO-04 give the headings.
